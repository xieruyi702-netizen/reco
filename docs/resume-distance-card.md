# 简历点：语音匹配距离卡精细化定价（2608 需求）

> 来源：飞书 PRD《2608 语音匹配距离卡新增档位与精细化定价》+ 技术方案《距离卡精细化定价》。
> 定位：这是 Soul 实习期间可 claim 的**业务项目**（区别于代码治理类的锁修复/并行化），
> 实习生 claim 的合理范围是**服务端/算法链路侧的匹配过滤与配置实现**，不含客户端和整个商业闭环。

---

## 一、这个需求在做什么（30 秒版）

语音匹配的"距离卡"原来只有一档：300km 召回、固定定价。这个需求把它做成**四档距离权益（30/100/200/300km）+ 按城市等级差异化定价**：

- 1/2 线城市展示 4 档（30km 更贵，40 币），3/4/5 线展示 3 档，低线城市兜底仅 300km（与现网一致）；
- 匹配分两阶段：先在用户选择的**严格档位内召回**，等待超时/连续空轮后**自动扩大到 300km**（单次最多扩大一次），结算按实际成功距离"多退少不补"；
- 目标：验证距离权益的价格弹性，提升次均价，位置类道具卡营收 +3%。

## 二、技术方案里可 claim 的实现点（实习生尺度）

| 实现点 | 内容 | 面试讲法 |
|---|---|---|
| **两阶段距离过滤** | link 服务的召回过滤算子扩展：严格阶段只召回 ≤ 用户档位的候选；超时/连续 2 轮空轮后扩大至 300km；扩大后原范围候选打分始终优先于范围外 | "我在距离过滤算子上实现严格→扩大的两阶段召回，核心约束是匹配成功率不能掉（护栏 88%），所以扩大后有原范围优先打分" |
| **itemAttr 协议扩展** | TravoResponse 的 itemAttr 新增 `distance` / `price` / `distanceLevels` / `hitDistanceExp` 字段，供客户端展示档位与价格；匹配结果通知（recallMatchResult）新增 `maxDistance` 供结算扣费 | "跨 4 个服务（planet-match-biz / travo / commlzn / link）的字段协议扩展，我负责算法侧的返回与透传" |
| **Apollo 配置化定价** | 档位价格 JSON 配置（`voice_match_distance_card_price_tiers`）、实验开关，改价格不发版 | "定价完全配置化，支持按城市等级出不同档位组合" |
| **降级兜底** | 任一关键配置缺失/价格倒挂/300km 基准档缺失 → 自动回落现网 300km 单档逻辑；Travo 不可用同样降级 | "商业化功能必须可降级：配置坏了就回到线上旧行为，用户无感" |
| **实验与护栏** | 三组实验（对照/算法推荐档位/用户自选），灰度 10% 起步；护栏指标：成功率 ≥88% 且降幅 ≤2pp、P90 等待时长增加 ≤5s；回滚条件 p<0.05 | "上线不是只有功能，有成功率护栏和统计显著的回滚条件" |

## 三、简历上的写法（可直接用）

> **语音匹配距离卡精细化定价**（Soul 实习项目，Java / Apollo / Redis / Dubbo 微服务）
>
> - 参与距离道具卡从"300km 单档"到"四档距离权益 + 城市等级差异化定价"的迭代，负责匹配链路（commlzn/link）侧的距离过滤与协议扩展；
> - 实现两阶段距离召回：严格档位内匹配，超时/空轮后自动扩大至 300km，单次最多扩大一次，扩大后原范围候选优先打分，保障匹配成功率（护栏 ≥88%）不因精细化召回下降；
> - 设计配置异常与下游不可用的多级降级：任一配置缺失或价格倒挂自动回落现网单档逻辑，商业化功能对用户无感回滚；
> - 档位价格、实验开关全量 Apollo 配置化，改价不发版；灰度实验三组对照，按统计显著性（p<0.05）决定扩量或回滚。

数据（+3% 营收等）是产品目标不是已验证结果，**简历别写成"营收提升了 3%"**，面试被问就说"还在实验灰度阶段，我负责的链路已上线"。

## 四、面试追问预案

| 追问 | 应答要点 |
|---|---|
| 为什么要"严格→扩大"而不是直接 300km？ | 产品要卖"更近"这个权益，直接 300km 等于没卖；但成功率是生命线，所以严格阶段短（10-30s）、连续空轮快速扩大，保成功率 |
| 扩大后为什么原范围优先打分？ | 用户花高价买的是"更近"，扩大后如果就近匹配了远处的人，等于权益没兑现；原范围优先保证实际结算大概率落在用户选的档位 |
| 结算为什么"多退少不补"？ | 预扣是锁资（防匹配中余额变化），实际距离可能比预扣档位更近（扩大场景），按实际档位退差价；"少不补"因为 300km 是承诺上限 |
| 配置降级怎么设计？ | 启动/每次读取校验完整性（档位存在、价格不倒挂、兜底档存在），任一不满足直接走老逻辑 + 监控告警；关键原则是降级路径=现网行为，天然安全 |
| 和你修的分布式锁缺陷是一个项目吗？ | 同一个服务（commlzn），不同模块：锁在延迟队列模块，距离卡在召回过滤链路——可以顺势把"迁移遗留债治理"和"业务迭代"两个故事串成"我在这条链路上既做过业务需求也做过底层治理" |
