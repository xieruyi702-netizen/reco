# 简历

## 实习经历

**2026.05 — 至今　　　　　　　　上海任意门科技有限公司（Soul）　　　　　　　　服务端开发实习生**

**实习背景**：负责语音匹配服务（商业化 reco 链路）的后端迭代与治理：并发问题修复、在线链路性能优化、延迟队列改造，兼顾 SQL 跑批平台与策略实验评估工具。

**核心工作**：

- **匹配服务并发正确性治理**（老系统迁移专项）：
  - 排查修复 super match 分布式锁缺陷：原实现 setnx 与 expire 分离，中间进程崩溃导致锁永久泄漏、用户无法再被匹配；改造为 SET NX EX 原子加锁，释放时校验锁归属防误删；同模块将延迟队列消费改为 Lua 原子弹出（ZRANGEBYSCORE + ZREM 单次往返），解决多实例重复消费，并按具体 member 删除规避同分任务误删；
- **在线链路性能优化**：
  - 串行批量 Redis 查询算子改造为分批并行：按 batchSize 切分，CompletableFuture 提交独立线程池并行执行后合并结果，在线推荐接口 P99 耗时显著下降；
  - 插件链路超时熔断：组内并行的插件设置单插件独立超时（Apollo 配置），慢插件超时降级不中断链路，保障在线接口耗时预算；
- **延迟队列链路迭代**：
  - 消费从同步逐条改为批量弹出 + 独立线程池并发执行，积压消化速度显著提升；批量大小、消费开关全量 Apollo 动态下发，线上可调可止血；
  - 付费续次卡延迟主叫策略迭代：延迟秒数接入实验参数（AB 对照），配合观察各分桶接通率；
  - 实验分桶信息高频读取增加本地缓存（容量 5 万 / TTL 5min），实验平台 RPC 调用量降一个量级；
- **策略实验工具平台**：内网 Hive SQL 批量跑批平台，双线程池分工（跑批执行池 Abort 快速失败保护下游 / 全局 SQL 队列池 CallerRuns 背压不丢数据）；多线程批量跑 SQL + 异步写飞书过程记录（端到端耗时降约 89%）；定时任务动态调度（cron 存 MySQL，ThreadPoolTaskScheduler 动态注册/重载，改周期配置不重启即生效，含防重入与错峰补偿）；构建 SQL 知识库供 Agent 写 SQL：对每份知识文档（表 DDL/业务口径/样例 SQL）提炼摘要向量化，向量检索 top-k 命中文档后加载全文组装上下文，生成 SQL 直查内部 Hive 验证想法与实验效果。

**技术栈**：Java、Spring Boot、Redis（分布式锁/Lua/ZSet 延迟队列）、Kafka、Apollo、Dubbo、MySQL、ThreadPoolTaskScheduler、飞书 Open API、GLM/DeepSeek LLM

## 项目经历

**Seckill — 商铺秒杀系统**

**项目简介**：Spring Boot + Redis 一主两从读写分离 + Kafka + MySQL + Docker 五容器编排；两条链路：商铺详情查询（读，多级缓存）与优惠券秒杀（写，Lua + 异步落库）；内置多模式压测与逐券一致性对账工具，以下数据均为宿主机实测。

**工作**：

- **读链路多级缓存**：L1 Caffeine（5s TTL）→ L2 Redis 从库（30min）→ MySQL；自研 Redis Bitmap 布隆过滤器（Murmur3 双哈希 + 参数公式推导），启动时从从库加载本地快照、查询零网络往返，写路径 pipeline 合并；互斥锁重建 + 空值缓存差值化 TTL 防击穿/穿透。压测：直连 MySQL 2.8 万 QPS → 多级缓存 **590 万 QPS**（L1 命中主导），P99 698µs → **1µs**，含 10% 恶意 id 全部拦截、DB 零穿透；
- **写链路高并发秒杀**：令牌桶限流（惰性补充，50 万突发验证通过数与理论值精确一致，全 fail-fast）→ Redis Lua 原子判定（库存 + 一人一单一次往返）→ Kafka 异步落库削峰（纯 DB 乐观扣减 3.2 万/s → 链路化 **+146%**）；
- **最终一致性**：Outbox 本地消息表——先落账再投递，消除"Redis 已扣减但消息未发出"的崩溃窗口；落账失败整体回滚 Redis（幂等 Lua 回补）；消费端手动 commitSync + earliest 重放，INSERT IGNORE + 唯一索引幂等，重复消费不刷新截止时间；混合压测后逐券校验 `redis余量 + 生效订单数 = 1000` **1000/1000 全部通过，零超卖**；
- **订单状态机与延迟取消**：支付 CAS 流转（0 待支付 → 1 已支付/2 取消）；未支付订单挂 Redis ZSet 延迟队列，500ms 定时扫描到期取消，DB 回补 + Redis Lua 幂等回补（SREM 门卫），支付成功主动移出队列；压测验证 600 单支付 + 400 单超时取消后 Redis 与 DB 余量精确一致，取消后可重新参与秒杀。

**技术栈**：Java、Spring Boot、MyBatis、Redis（Lua/主从读写分离/布隆过滤器）、Kafka（Outbox/手动 offset）、Caffeine、MySQL、Docker Compose
