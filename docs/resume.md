**核心工作**：

## 项目经历

**Seckill — 商铺秒杀系统**

**项目简介**：Spring Boot + Redis 一主两从读写分离 + Kafka + MySQL，Docker Compose 七容器编排（Nginx 轮询负载均衡 + 双 app 实例）；两条链路：券详情查询（读，多级缓存）与优惠券秒杀（写，Lua + 异步落库）；JMeter 端到端压测验证，以下数据均为实测。

**工作**：

- **读链路多级缓存**：布隆过滤器（Redis Bitmap + 本地快照零网络）→ L1 Caffeine → L2 Redis 从库 → MySQL；互斥锁重建防击穿、空值缓存防穿透、TTL 随机抖动防雪崩（避免同批 key 同时过期打穿 DB）。压测：直连 MySQL 2.8 万 QPS → 多级缓存 **590 万 QPS**，P99 698µs → **1µs**，恶意 id 全拦截、DB 零穿透；
- **写链路高并发秒杀**：令牌桶限流（50 万突发验证通过数与理论值精确一致）→ Redis Lua 原子判定（库存 + 一人一单）→ Kafka 异步落库削峰，判定吞吐较纯 DB 乐观扣减 **+146%**；
- **最终一致性**：Outbox 本地消息表先落账再投递，消除崩溃丢消息窗口，落账失败整体回滚 Redis；消费端手动 commitSync + earliest 重放 + 唯一索引幂等，消费失败重试后转死信 topic；混合压测逐券对账 `redis余量 + 生效订单数 = 1000` **1000/1000 通过，零超卖**；
- **多实例适配与状态机**：支付 CAS + ZSet 延迟队列超时取消（幂等回补、可重新参与）；Nginx 轮询 + topic 双分区双实例并行消费，扫描分布式锁互斥，雪花 ID 解决订单号撞号；券详情缓存跨实例失效——先更 DB → 删 L2 → pub/sub 广播踢 L1，TTL 兜底。
- **端到端验证**：JMeter 压测 Nginx → 双实例全链路 **5338 req/s 零错误**；组件级压测对照理论值验证设计正确性（限流 50 万突发通过数与令牌桶公式精确吻合）；一切数字可复现——compose 一键起环境、压测脚本与对账工具内置。
